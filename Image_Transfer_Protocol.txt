New characteristics:
- Control:
	- Client side:
		- image start/can you take an image (can I send an image)
		- image end (no more data to send for an image)
	- server side (esp32):
		- error (used to let the client know that the operation was not successful or 				cannot start image transfer)
		- ok (wrote byte successfully to file or can initiate image transfer
- Image:
	- reserved for chunks of image
	- Only used by the client: assume client behaves and only sends image data here.



We will assume that the server only stores one image at a time (for simplicities sake)

BoardState Enum (thread safe):
- READY: ready to receive image data
- WRITING: image data is being sent, do writes
- DISPLAYING: all image data has been sent, stop writing to file and start e-paper display

File* image:
- not thread safe, will only be modified by the image characteristic callback


Asynchronous flow chart (per characteristic thread)

Control:
- client sends start byte
- Server receives start byte
	- READY:
		sets BoardState to WRITING and send ok byte back to client
	- WRITING:
		- clears current image file, sets state to READY and then sends error byte to 
client
	- DISPLAYING:
		- sends error byte to client
	- note: client will only send data to image characteristic after receiving ok

- client sends end byte
- server receives end byte, 
	- READY:
		- sends error byte to client

updates state to WRITING and sends ok byte to client:
	- client will stop sending data to image characteristic after receiving ok.
Image:
- READY, DISPLAYING:
	- ignore any image data sent
- WRITING:
	- write image data to file using pointer.



After all data is transferred, server updates state to DISPLAYING and begins updating the e-paper display. after the display is updated, it sets state to READY.

Here is the standard flow:
client sends image start byte, then waits (control)
server sets write bool to true clears out image file (in case of any previous issues), returns ok byte and waits (control)
client sends first chunk of image then waits (image)
server gets first chunk of image, writes it to memory using pointer and then returns ok (image)
server keeps sending bytes and waiting, server keeps writing and returning (image_
client sends image end byte
server sets write bool to false, then returns ok (image)
after the exchange server starts writing image

Now here is the error handling at each step:
client sends image start byte, then waits
 - Server does not respond after a set timeout:
	- client shows error on app
 - server already has a write in progress (indicated by write bool)
	- server returns error byte, and client shows error
	- server clears out incomplete image file.
	- server clears write bool
server returns ok byte and waits
- client doesn't respond by the timeout
	- server sets write bool to false
client sends chunk of image then waits
- Server does not respond after a set timeout:
	- client shows error on app
- Server fails write:
	- server returns error byte, and client shows error
	- server clears out incomplete image file
	- server sets write bool to false
server gets chunk of image, writes it to memory using pointer and then returns ok
- client doesn't respond by the timeout
	- server clears out incomplete image file
	- server sets write bool to false
client sends image end byte
 - Server does not respond after a set timeout:
	- client shows error on app
 - server does not have a write in progress:
	- server returns error byte, and client shows error
server returns ok.
- No failure here.
